# Бесконечная процедурная карта с чанк-стримингом

## Что делаем

Убираем фиксированный размер карты (сейчас 50×50). Карта становится бесконечной во все стороны, тот же паттерн генерации (Перлин-шум для типа тайла и воды), но без границ. Тайлы данных генерируются лениво по первому обращению и кэшируются. Рендер (спрайты тайлов + туман войны из прошлой задачи) подгружается/выгружается блоками вокруг камеры по мере движения игрока — не создаём разом спрайты на весь мир.

Заодно переводим на «без границ» всё, что раньше опиралось на ширину/высоту карты: поиск пути NPC, AI-поиск целей (еда/вода/бегство), выбор точки спавна игрока, рамку выделения тайла под курсором.

## Текущая архитектура

- `WorldMap` — на старте генерирует фиксированный 2D-массив `width×height` тайлов сразу целиком (Перлин-шум по `(x,y)`, не зависит от размера — уже готов к бесконечности). `findPath` — BFS по плоским массивам `visited`/`parent`, размер `width*height`, знает границы. `getWidth/getHeight/getAllTiles` — раскрывают фиксированный размер наружу.
- `WorldQuery.findNearestTileInRadius` — сканирует прямоугольник вокруг позиции, сейчас зажимает его в `[0, width-1]×[0, height-1]`.
- `MainScene.createMap()` — один раз в `create()` создаёт спрайт тайла + спрайт тумана на каждую из 2500 клеток сразу, хранит в двух `Map` по ключу `"x,y"`. `updateTileVisuals`/`updateTileFog` каждый кадр проходят по всем тайлам.
- 4 AI-поведения (`search-food`, `search-prey`, `search-water`, `flee-predator`) при выборе случайной точки для перемещения зажимают её в границы карты через `worldMap.getWidth()/getHeight()`.
- `spawnPlayer` ищет проходимую клетку рядом с геометрическим центром фиксированной карты.
- `updateSelectionMarker` скрывает рамку наведения, если клетка вне `[0, width)×[0, height)`.

## Подход

### 1. `WorldMap` — бесконечная, ленивая генерация

Больше не хранит `width/height`, не строит массив заранее. Внутри — одна `Map` «мировые координаты тайла → данные тайла». `getTile(x, y)` при отсутствии значения генерирует тайл той же функцией шума (она уже принимает произвольные `x,y`, ничего не меняется в самой генерации) и кладёт в кэш; возвращает тайл всегда (раньше мог вернуть `null` за границей — границ больше нет, упрощаем сигнатуру и убираем ставшие мёртвыми проверки на `null` у вызывающего кода).

`getWidth/getHeight/getAllTiles` и не привязанные к радиусу версии `findNearestVegetation/findNearestWater` (сканирование всей карты целиком) удаляются — первые два бессмысленны для бесконечной карты, вторые нигде не вызываются (реально используется только версия из `WorldQuery` с радиусом).

`findPath` переписывается с плоских массивов фиксированного размера на `Map`/`Set` по строковому ключу координаты — работает для любых, в т.ч. отрицательных координат. Поиск ограничивается разумным радиусом вокруг стартовой точки (с запасом сверх расстояния до цели), чтобы BFS не мог бесконечно расползтись по бесконечной карте, если цель недостижима.

### 2. `MainScene` — чанк-стриминг рендера

Вводим чанк — блок 16×16 тайлов, единица только для рендера (загрузка/выгрузка спрайтов), в данных `WorldMap` понятия чанка нет вообще. Каждый кадр по видимой области камеры (`camera.worldView`, с запасом в один чанк) вычисляется набор нужных сейчас чанков. Чанки, которых нет в наборе, но раньше были загружены — выгружаются (спрайты тайла и тумана уничтожаются, записи из карт `tileSprites/tileFogSprites/tileFogAmount` удаляются). Чанки из набора, которых ещё нет — загружаются (создаются спрайты тайла+тумана на каждую из 256 клеток, как раньше делал `createMap`, но по требованию).

`updateTileVisuals`/`updateTileFog` теперь проходят не по вообще всем тайлам карты, а только по уже загруженным спрайтам (`tileSprites`/`tileFogSprites`) — естественно ограничено видимой областью, без доп. усилий.

Анимация «выцветания» (насколько тайл сейчас скрыт) при выгрузке чанка теряется — не проблема, это чисто визуальное промежуточное состояние. А вот сам факт «тайл уже видели» — постоянный флаг `everSeen` на данных тайла в `WorldMap` (переживает выгрузку/загрузку чанка, т.к. кэш тайлов не выгружается вместе со спрайтами). Три состояния тумана на тайл: никогда не видели → чёрный, непрозрачный, ничего не видно; видели, но сейчас не в поле зрения → приглушённый серый (старое поведение); прямо сейчас в поле зрения → полный цвет. Переход «чёрный → цвет» при первом попадании в поле зрения и «серый → цвет» при повторном используют одну и ту же быструю анимацию; «цвет → серый» при выходе из поля зрения — медленную. Обратного перехода в чёрный не бывает — `everSeen` необратимо ставится в `true`.

### 3. AI и поиск пути без границ

4 поведения, использовавшие `getWidth/getHeight` для зажатия случайной точки поиска/бегства в границы карты — теперь просто не зажимают её (весь смысл зажатия был «не выйти за край карты», края больше нет), точка по-прежнему проверяется на проходимость перед использованием. Заодно уходит мёртвая после этого ветка «зажатие сработало — развернуть угол поиска».

`WorldQuery.findNearestTileInRadius` — убираем зажатие прямоугольника поиска в границы карты, просто сканирует прямоугольник вокруг позиции как есть (`getTile` теперь в любом случае вернёт тайл, сгенерировав его при необходимости).

### 4. Спавн игрока

Раньше — проходимая клетка рядом с центром фиксированной карты. Теперь — раскручивающийся квадратный поиск от мировых координат `(0,0)` наружу до первой проходимой клетки (то же самое семантически, просто без привязки к размеру карты, которого больше нет).

## Известные ограничения (осознанно не решаются сейчас)

- Кэш данных тайлов внутри `WorldMap` растёт и никогда не освобождается (в отличие от рендер-спрайтов, которые выгружаются вместе с чанком) — при очень долгой сессии с большим исследованным миром это рост потребления памяти. Для обычной игровой сессии не критично, чинить заранее — преждевременная оптимизация.
